# 区域自动采集

本文说明按真实地图区域或地名启动自动导航与摄影的本地控制页。  
更新日期 2026-11-09。

## 启动

使用完整 Windows x64 采集交付包，解压到新的真实目录。包需包含匹配的 `cpp-algo.exe`、`go-service.exe`、MaaFramework 5.14.3 DLL、导航网格、定位模型、底图和 Pipeline。首次启动器准备 Python 3.12.10 与锁定依赖，SDK 依赖安装需要联网。以仓库根目录作为当前目录运行。

```cmd
scripts\capture\capture.cmd serve
```

本地页面默认位于 `http://127.0.0.1:8780/`。准备好 Python 环境后也可直接启动服务，`--no-browser` 保留终端给出的地址。

```cmd
local\envs\capture-windows-py312\Scripts\python.exe -B -m tools.capture.server --workspace . --port 8780
```

服务绑定本机回环地址。端口被占用时需选择其它端口。所有任务、计划、日志和临时文件保存在所选工作区的 `local/`。

## 选择区域并开始

在游戏中进入大世界后，输入完整地名，或点击地图上的区域标记。目录从现有 `teleport_anchors.json`、SceneTeleport 锚点登记表及实际传送入口建立映射。“缘缘庄”对应武陵“祀的画”的真实传送锚点。名称未匹配或对应多个锚点时，页面要求选定明确区域。

名称代表锚点所在位置。默认采集范围是锚点周边半径 60 个 BaseNav 底图像素，可调整半径，或在地图上点击圈出多边形。默认采样间距为 20 个底图像素，每点拍摄 8 个方向，方向间隔为 45°，采样点预算为 160。可选择导航层级或输入层高，以区分同一平面位置上的多层可走面。

点击“开始采集”会规划可达采样点并直接启动任务。“预览采集点”可单独显示规划路线、可达点数、摄影总数和排除数量。地图拖动可平移，滚轮可缩放。圈选坐标、路线与采样点使用同一 BaseNav 底图坐标系。导航网格显示会抽样绘制三角面，实际规划使用完整导航数据。

开始后在五秒准备时间内切回游戏。任务使用已有传送入口进入目标区域，通过 `MapNavigateAction` 前往采样点，由原生摄影动作闭环调整镜头朝向并接收同帧图像和定位。游戏画面、地图解锁、传送点解锁及账号当前状态会影响执行结果。

## 任务控制与导出

页面显示任务 ID、状态、完成计数、会话、generation 和本地事件。可暂停、恢复、停止，也可输入旧任务 ID 读取状态。导航执行端负责释放输入和确认命令。自动任务暂停会关闭原生连接，恢复时使用新会话和时钟接续计数，已提交批次保持不可变。

“导出冻结包”可选择本次页面读取到的会话，或导出最新会话。导出通过正式 CaptureBundle 校验后给出本地目录。未提交尝试与诊断文件保留在任务目录中。图像选择状态保持 `pending`，导航位置和朝向作为粗先验，真实相机位姿、俯仰、FOV、原生渲染时间及几何质量保持未知。离线处理入口见[输入准备](offline-preparation.md)。

使用 CLI 可直接输入名称启动。完整参数以源码命令入口为准，任务 ID 应使用新的值。

```cmd
scripts\capture\capture.cmd auto --region "缘缘庄" --radius 60 --spacing 20 --views 8 --task yuanyuan-auto
```

## 数据与运行边界

规划固定区域目录、底图坐标系、选区、资源 SHA-256、采样点、真实网格层高与镜头意图。坐标转换复用现有 BaseNav 数据，游戏总览界面的 `region3d` 点击坐标仅供原有传送界面使用。运行资源发生变化时需要重新规划。

本地服务校验 Host、Origin、随机控制令牌、JSON 请求类型和请求大小，静态资源通过白名单读取。页面加载与规划查询只读取资源，游戏控制由显式开始或恢复动作触发。独立的世界网页继续消费 WorldRelease，采集页面负责本机任务控制。
